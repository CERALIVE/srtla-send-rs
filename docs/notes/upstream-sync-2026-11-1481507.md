## Adapted tests

- `crates/srtla-core/src/connection/ack_nak.rs`,
  `retransmitted_sequence_ack_preserves_rtt_floor_and_delivery_accounting` (fork test):
  calls `SrtData::set_retransmit`, upstream's new name for `set_srt_data_retransmit`.
  Assertions unchanged.
- No upstream test body changed in the merge.
- `src/sender/links.rs`, `a_pending_pair_read_leaves_the_runtime_thread_free` (new, with
  `3fc0982`, reworked in `176449b`): the IP file is a FIFO. A blocking open of its write
  end marks the read as started, the write end is then held so the read keeps waiting,
  and the `current_thread` runtime has to keep running meanwhile. Without the fix it
  fails after its 5 s bound.
- `tests/signal_shutdown.rs`, `sigterm_exits_cleanly_while_a_bind_map_reload_is_stuck`
  (new, with `91a409e`): the real binary with `--bind-map`, its IP file swapped for a
  FIFO, a `SIGHUP` whose read is then held open, and `SIGTERM` must exit 0 within 2 s.
  Before the fix the process did not exit within 10 s. The file's tests also bind listen
  port 0 now instead of probing for a free port, which one run lost to another socket.
- `src/tests/connection/connection_tests.rs`, `data_not_padded` (fork test, `1ba32a6`):
  also sends a 20-byte DATA datagram and checks its exact length and bytes. Padding DATA
  to the 32-byte control floor makes it fail; the 1316-byte case alone could not show it.

## Follow-ups

- Measure `current_thread` and the system allocator on the RK3588 device. Upstream's
  numbers are from loopback on a desktop host; `scripts/bench-loopback.sh` was not run.
- Upstream `602c49e` adds a `deslop-please` architectural lint to CI. The fork CI does
  not run it; adopting it means a pinned, checksummed tool download in `ci.yml`.
- Upstream doc defects to report upstream: `docs/EXTENDED_KEEPALIVE.md` still links
  `crates/srtla-protocol/src/builders.rs`, which `4aeba78` removed, and
  `crates/srtla-core` doc comments still name `SrtlaConnection::note_sent`, which no
  longer exists. Both are kept as upstream wrote them.
- `scripts/netns_test_gate.sh` does not register `netns_arrival_reports`, added in the
  `8677bb49` sync, so the gate script never runs it. It also runs each target's tests in
  parallel threads, while `crates/network-sim/src/harness.rs` names the veth pairs after
  the process id alone (`vs{pid:x}_{i}`), so sibling tests collide on `ip link add`. Pass
  `--test-threads=1` as upstream CI does, or name the pairs per test.
- `ci/build-deb.sh` depends on the caller's umask: under 0077 its control directory is
  0700 and `dpkg-deb` refuses it. Creating the directory with an explicit mode would
  make local packaging independent of it.
- Upstream observations from the second review, not changed here:
  `crates/srtla-core/src/selection/enhanced.rs` builds a full telemetry snapshot
  (`telemetry(0)`) per packet to read one field, and the reset test in
  `crates/srtla-core/src/connection/batch_send.rs` asserts the slab's private layout
  (`buf.is_empty()`) rather than that no old datagram drains after a reset.
- Two overlapping `SIGHUP` reloads with `--bind-map` can finish out of order, and the
  older result is then applied last. `main`'s multi-thread runtime already allowed this.
  Serialize the reads, or tag each request and drop superseded results.
- `tests/signal_parity.rs`, `tests/session_bytes_integration.rs` and
  `tests/startup_bind_ordering.rs` still probe for a free UDP port and hand it over, the
  race `tests/signal_shutdown.rs` dropped.
- The follow-ups in the `8677bb49` ledger still apply.
